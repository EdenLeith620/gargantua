# GARGANTUA — Schwarzschild Black Hole Raytracer

全屏实时交互网站。黑洞本体由**单个全屏 Fragment Shader 现场积分史瓦西零测地线**生成——
没有黑球、没有平面圆环、没有贴图、没有视频、没有截图。屏幕上的每一个像素都是一条光子
轨迹被真正求解出来的结果。

原生 HTML / CSS / JavaScript + ES Modules，**无需构建**，`vendor/` 里只有一个
`three.module.js`（加一个 `OrbitControls.js`），HDR Bloom / ACES / 色散 / 暗角 / 颗粒
全部按 WebGLRenderTarget 手写，不依赖 `EffectComposer` 或任何后处理插件。

---

## 1. 启动

ES Modules 需要 HTTP 源（`file://` 会触发 CORS），因此需要一个静态服务器。项目自带一个
零依赖的：

```bash
cd gargantua
node scripts/serve.mjs          # 默认 8137 端口
# 打开 http://127.0.0.1:8137/
```

指定端口 / 根目录：

```bash
node scripts/serve.mjs 9000 .
```

任何等价方式都可以，例如：

```bash
python3 -m http.server 8137
npx serve -l 8137
php -S 127.0.0.1:8137
```

**环境要求**：支持 WebGL2 的浏览器（Chrome / Edge / Firefox / Safari 16+）。
需要 WebGL2 是因为 HDR 管线使用 `RGBA16F` 渲染目标；WebGL1 下会自动降级但仍可运行。

## 2. 物理：它是怎么算出来的

### 2.1 测地线方程

采用几何单位，史瓦西半径 `r_s = 1`，几何质量 `M = 1/2`，`c = G = 1`。

史瓦西时空中零测地线的轨道方程（Binet 形式）为

```
d²u/dφ² + u = (3/2) r_s u²      ,  u = 1/r
```

取第一积分并利用 `L = r² dφ/dλ`，可以证明它**严格等价**于三维笛卡尔形式的中心力方程

```
d²x/dλ² = −(3/2) r_s · h² · x / r⁵      ,  h = |x × dx/dλ|
```

（验证方式：由上式回推径向方程 `r'' = h²/r³ · (1 − (3/2) r_s/r)`，再与 Binet 形式对照。）

因为方程是中心的，`x × v` 在数值积分中是一个守恒矢量——这正是下面薄盘多普勒项能够
良定义且精确的原因。

### 2.2 初始条件：静态观察者，不是平直近似

相机不在无穷远，所以射线初值必须取自**静止观察者的局部正交标架**：

```
E_loc   = E / √(1 − r_s/r₀)            （局部测量能量）
cos ψ   = (dr/dλ) / E                  （ψ = 与径向的夹角）
b = L/E = r₀ sin ψ / √(1 − r_s/r₀)     （碰撞参数）
```

固定 `E = 1` 得到坐标速度

```
v = cos(ψ)·r̂ + tangent / √(1 − r_s/r₀)
```

于是 `|x × v| = b` 以机器精度守恒。绝大多数实现直接用平直空间的视线方向当速度初值，
在相机较近时会造成可观的几何误差；这里没有用那个近似。

### 2.3 积分器

自适应步长 + 两种积分器，随质量档切换：

| 积分器 | 说明 | 用在哪 |
|---|---|---|
| Velocity Verlet | 2 次力计算，对称辛格式，长期行为稳定 | Standard |
| 经典 RK4 | 4 次力计算，临界区允许更大步长 | High / Cinematic |

步长同时受两个约束限制：

```
dλ_ang = uStepAngle · r²  / max(h, 0.02)     限制单步角位移
dλ_rad = uStepRadial · r                    限制单步径向相对位移
dλ     = clamp(min(dλ_ang, dλ_rad), 0.0035, 4.0)
```

远处径向约束主导，射线大步滑行；光子球附近角约束接管，把临界轨道解开。采用
**最大迭代数 + 提前 break**（`i >= uMaxSteps` / 落入视界 / 逃逸 / 不透明度饱和）。

**盘面穿越用线性插值精确定位到 y = 0**，因此盘边缘的锐利程度与测地线步长完全无关——
这是粗步长下仍然能出干净的盘面轮廓与多次像的关键。

### 2.4 视界、光子环、多次穿越

* 事件视界：`r ≤ r_s` → 该像素彻底黑（不加任何自发光，"深黑"是算出来的，不是画上去的）。
* 光子环：不稳定圆轨道 `r = 3M = 1.5 r_s`，临界碰撞参数 `b_crit = 3√3 M = 2.598 r_s`。
  它由测地线自然涌现，不做任何增强。
* 多次盘穿越：积分过程中**每一次** `y = 0` 交叉都按由近及远（front-to-back）累积，
  于是近侧、远侧、以及被引力弯折到盘上方/下方的二次、三次像全部自动出现。

### 2.5 观测辐射：多普勒 + 引力红移

开普勒圆轨道：`Ω = √(M/r³)`，`u^t = 1/√(1 − 3M/r)`。发光体与无穷远静止观察者之间的
总频移比为

```
g_full = √(1 − 3M/r) / (1 − Ω · b_φ)      ,  b_φ = L_φ / E
```

它干净地分解为一个纯引力部分和一个纯多普勒部分：

```
g_grav = √(1 − r_s/r)          D = g_full / g_grav
```

利用 `I_ν / ν³` 不变：

```
T_obs = T_em · g_grav^a · D^b
I_obs ∝ I_em · (g_grav^a · D^b)⁴          (bolometric)
```

`a = uRedshift`、`b = uDoppler`，取 1.0 即物理真值。

**符号上的一个坑（本项目真实踩过）**：`b_φ = L_φ/E` 里的符号是 `+(x × v)_y / E`，
不是 `−(x × v)_y / E`。因为积分参数 λ 从相机向外走，`dx/dλ` 是真实光子动量的
**时间反演**——时间反演下空间动量翻号而能量保持为正。取错符号的后果是"多普勒增亮的
那一侧画反了"，而且看起来完全合理，直到你把它和湍流实际流动方向对起来才会发现。
调试视图 **4** 就是专门为此准备的。

**一个可以直接对照的量**：`r = 3 r_s` 处能够逃逸的光子被 `b_crit = 2.598 r_s` 限制，
`sin ψ ≤ 0.707`，因此蓝移是有上限的。最终迎向侧/背向侧的亮度比约为 **16 倍**，
而不是朴素相对论给出的 ~90 倍。这是可以用来判断实现是否正确的硬指标。

### 2.6 吸积盘

* **温度剖面**：Shakura–Sunyaev 薄盘 `T ∝ r^(−3/4)(1 − √(r_in/r))^(1/4)`，
  归一化到 `T⁴` 峰值恰为 1（峰值位于 `r = 1.361 r_in`）。默认内半径 3.0 `r_s`，
  即 `6M`——史瓦西时空的 ISCO，取更小值会进入不稳定圆轨道区。
* **颜色**：由 `T_obs` 经普朗克轨迹 → 线性 sRGB 得到色度，再归一化到单位亮度。
  于是**色度与辐射亮度解耦**：亮度全部来自 `T⁴` 剖面与 `g⁴` 增亮，颜色只由温度决定。
* **湍流**：噪声在**与本地开普勒流共动的参考系**中采样，差速剪切自动把流场卷成
  螺旋丝状——没有任何一处手写的螺旋几何。另外叠加一个静态对数螺旋相位
  `1.15·ln(r/r_in)`，保证第一帧就是被剪切过的形态。
* **湍流必须同时调制不透明度与发射率**。只调制不透明度是无效的：掠射时 `τ` 迅速饱和，
  `α` 钉死在 1，整张盘会塌成一块**没有结构的灰板**——这是本项目迭代中真实出现过的
  失败形态。自由-自由发射率 ∝ ρ²，所以发射率拿到的是平方（更陡）的调制曲线。
* **几何**：平面穿越项承担主体成像（光深 `τ = κ·L·ρ`，`L = 2H/|cos θ|`），
  另加一层很轻的体渲染日冕软化盘面上下边缘。

### 2.7 背景天球

* **星空**：三层 cell-based 星场（尺度 54 / 148 / 402）。每个 cell 只查一次——
  星点 PSF 远小于随机偏移量，所以单次采样在数学上就足够，不会有跨 cell 的渗漏。
  星等分布 `mag^4`，色温 2500–15000 K，并对亚像素星点做**流量守恒**处理
  （`flux = min(1, rad/aa)²`），否则远处星空会糊成灰雾。
* **银河**：在倾斜银道面上用 fbm 生成云带 + 尘埃带 + 银心亮斑。
* 两者都**在射线逃逸后的最终方向上采样**——所以爱因斯坦环、星空被透镜拉成的弧
  全部自动出现，不需要任何额外代码。

### 2.8 射线生成与视场锚定

像素 `(ndc.x, ndc.y) ∈ [−1,1]²` 处的射线方向为

```
d = normalize(uCamForward + uCamRight·(ndc.x·tanHalfFov·aspect) + uCamUp·(ndc.y·tanHalfFov))
```

`tanHalfFov` 是**垂直**半张角，水平方向由 `aspect` 撑开。这在横屏下没问题，
但在竖屏（手机 390×844，`aspect ≈ 0.46`）会让水平视场塌缩到垂直视场的 46%，
整个黑洞被放大到冲出画面。因此 `aspect < 1` 时改为**锚定水平轴**：

```
tanHalfFov = tan(fov/2) / aspect          (aspect < 1)
```

等效于 CSS 的 `object-fit: contain`：竖屏下视场整体变宽，黑洞连同周围星空一起入画。
横屏（`aspect ≥ 1`）路径**完全不变**，因此桌面端构图不受影响。实测竖屏下
`preset 2`（极地俯视）的暗部占比由 18% 变为 62%——多出来的全是原本被裁掉的星空。

**音频为什么是无缝的**：`make-ambient.mjs` 里每一个分音频率、每一个 AM 速率都被
snap 到 `1/30 Hz` 的整数倍，因此每个分量在 30 秒窗口内恰好完成整数个周期，
`sample[N-1]` 与 `sample[0]` 天然接得上——不靠交叉淡化掩盖接缝。生成器会报告
环绕步长与平均相邻步长之比（实测 **0.04×**，即接缝处的样点跳变完全落在正常
相邻样点差值的波动范围内）。

## 7. 质量档

| 档 | 渲染比例 | DPR 上限 | 最大步数 | 步长(角/径向) | 积分器 | fBm 层 |
|---|---|---|---|---|---|---|
| Standard | 0.55 | 1.0 | 260 | 0.062 / 0.078 | Verlet | 3 |
| High | 0.85 | 1.5 | 520 | 0.045 / 0.058 | RK4 | 4 |
| Cinematic | 1.00 | 2.0 | 900 | 0.032 / 0.042 | RK4 | 6 |

另外有一个静默的**自适应分辨率**：连续低于 20 FPS 时按 0.09 步长下调 DPR（下限 0.62），
高于 52 FPS 时缓慢回收。避免移动端一开始就卡死。切换质量档会重置该系数。

移动端首次访问会自动选择 Standard；`navigator.hardwareConcurrency ≥ 4` 的桌面默认 High。
Retina 通过 `setPixelRatio` 生效——HUD 是 DOM，因此任何档位下文字都是原生清晰度。

## 8. URL 截图自动化接口

**URL 形式**（无需任何交互，可直接喂给无头浏览器）：

```
index.html?shot=1&t=18&q=cinematic&preset=0&view=0&w=1920&h=1080&dpr=1&dl=1
```

| 参数 | 含义 |
|---|---|
| `shot=1` | 进入确定性模式：冻结电影镜头到 `t`，时间不再推进 |
| `t` | 冻结的场景时间（秒）。给定 `(t, 参数, 质量档, 分辨率)` 时结果逐位可复现 |
| `q` | `standard` / `high` / `cinematic` |
| `preset` | 0–3 视角预设 |
| `view` | 0–9 调试视图 |
| `hud=0` | 隐藏 HUD（出图用） |
| `p=mass:1.4,diskTemp:14000` | 批量覆盖任意参数 |
| `cam=az,el,r,fov` | 直接指定相机 |
| `dl=1` | 触发下载 |
| `settle=12` | 出图前的稳定帧数（默认 8） |
| `nostore=1` | 忽略并使用后清空 localStorage |

**JS 形式**（`window.GARGANTUA`）：

```js
await window.GARGANTUA.ready;                       // 首帧 + 稳定帧完成后 resolve
window.GARGANTUA.setParams({ diskTemp: 14000 });
window.GARGANTUA.setQuality('cinematic');
window.GARGANTUA.setView(4);
await window.GARGANTUA.renderAt(12.5, 8);           // 冻结时间 + 稳定 8 帧
const png = await window.GARGANTUA.capture();       // -> PNG data URL
window.GARGANTUA.getState();                        // 全量状态（含相机）
window.GARGANTUA.getStats();                        // FPS / 帧时 / 渲染分辨率 / 平均步数
```

就绪信号：`document.documentElement[data-gargantua="ready"]`、`window.__GARGANTUA_READY__`、
`window.__GARGANTUA_SHOT__`（出图数据）、以及 `gargantua-ready` / `gargantua-shot` 事件。

> **注意**：`shot=1` 模式下"就绪"由出图路径发出，而不是由普通帧循环发出。
> 两者都发会在确定性时间和稳定帧生效之前就被外部抓拍——这是本项目修过的一个真实竞态
> （表现为截图全黑但页面内统计正常）。

## 9. 状态持久化与错误恢复

* **持久化**：21 项参数、质量档、调试视图、视角预设、电影镜头开关、HUD/面板显隐、

## 11. 已知取舍

* **无自旋**：这是史瓦西解，不是 Kerr。没有参考系拖曳、没有 ISCO 随自旋移动、
  没有拖曳造成的盘面不对称。`Ω = √(M/r³)` 是开普勒的，不是 Kerr 的。
* **薄盘近似**：盘被当作光学厚的地平面 + 轻度体日冕，没有做真正的辐射转移
  （无散射、无频率相关的光深、无康普顿化）。
* **只有强度阶跃的红移**：`I ∝ g⁴` 是 bolometric 关系；没有对观测波段做逐频率积分。
* **湍流是程序化的，不是磁流体力学**：共动系 fbm 复现了剪切级联的**形态**，
  不声称它是 MRI 湍流的解。
* **`uDiskGain = 0.33` 是显示增益**。它只缩放绝对幅度——对一个没有绝对光度参考的
  场景本就任意的量。`T⁴` 剖面、`g⁴` 增亮、16 倍不对称比等**形状**完全不受影响。
* **盘面湍流的相位会随时间持续卷绕**（差速旋转的必然结果）。默认流动速度下大约
  数分钟量级才会细密到影响观感，按 `R` 重置即可。
